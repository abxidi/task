# Task 原生 macOS 任务管理应用设计规格

日期：2026-07-13
状态：用户已确认，进入开发交接
产品名称：Task

## 1. 产品目标

Task 是一款原生 macOS 个人任务管理应用。它面向需要长期管理工作与个人项目、同时希望更理性地分配精力的用户。

产品保留传统任务清单与项目看板的执行效率，但把“紧急度 × 重要度”坐标作为核心决策界面。AI 是可选增强能力，而不是应用运行的前置条件。

首个版本必须满足以下原则：

- 原生 macOS 体验，可构建为可安装的 `.app`。
- 所有任务数据只保存在本机，不提供账号、云同步或多人协作。
- 未配置 AI 时，任务、看板、指标和本地规划功能完整可用。
- 任务编辑首先服务于描述和拆解，不强迫用户填写管理属性。
- 优先级坐标、指标和 AI 建议必须可解释，不暗中修改用户数据。

## 2. 范围

### 2.1 首版包含

- 优先级地图：正方形四象限、拖拽设置、格点吸附、键盘微调。
- 任务列表：今天、未来 7 天、全部任务、已完成。
- 项目：创建、编辑、归档和颜色标识。
- 项目看板：默认工作流列、任务拖拽、自定义列名和顺序。
- 任务编辑：标题、描述、子任务和折叠的任务设置。
- 本地数据指标：完成率、计划负载、高重要任务、计划健康度、完成趋势和象限分布。
- 可选 AI：任务拆解、周计划草案、依赖提示和负载风险提示。
- 本地提醒：用户显式设置提醒时间后，通过 macOS 本地通知提醒。
- 本地设置：每日可投入时间、工作日、默认项目、AI 服务配置和全局唤起快捷键。
- JSON 备份：本地导出和导入，导入前提供校验结果。

### 2.2 首版不包含

- iCloud 或第三方云同步。
- 用户账号、团队协作、评论和权限管理。
- Web、iOS 或 Windows 客户端。
- 日历双向同步。
- AI 自动后台分析或未经确认的任务修改。
- 插件市场和第三方自动化系统。

## 3. 信息架构

应用使用固定左侧导航，主工作区随视图切换，右侧检查器随选中任务变化。

| 一级入口 | 目的 | 主要内容 |
| --- | --- | --- |
| 优先级地图 | 决定先做什么 | 四象限坐标、周期筛选、项目筛选、任务检查器 |
| 任务列表 | 快速录入与执行 | 今天、未来 7 天、全部任务、已完成 |
| 项目看板 | 推进项目流程 | 指标、趋势、象限分布、可拖拽工作流列 |
| 数据洞察 | 回顾个人执行情况 | 周/月趋势、完成率、负载与优先级分布 |
| 设置 | 管理本地行为 | 默认值、容量、通知、全局唤起快捷键、AI 服务、数据导出 |

侧栏下方显示“本机工作区”，明确数据只存储在当前 Mac。

## 4. 优先级模型

### 4.1 坐标定义

- 横轴：紧急度，整数 `-3...+3`。
- 纵轴：重要度，整数 `-3...+3`。
- 两个维度共有 `7 × 7`、即 49 个离散坐标组合。
- 地图固定为 `1:1` 正方形，横纵轴单位距离完全一致。
- 最小可用尺寸为 `360 × 360 pt`；窗口缩小时等比缩放，不拉伸。
- 新任务默认坐标为 `(0, 0)`，表示尚未判断优先级。

四象限定义：

| 条件 | 象限 | 用户含义 |
| --- | --- | --- |
| `紧急度 > 0 && 重要度 > 0` | 立即处理 | 尽快安排并执行 |
| `紧急度 < 0 && 重要度 > 0` | 重点规划 | 预留时间，避免转为紧急 |
| `紧急度 > 0 && 重要度 < 0` | 适当委派 | 降低个人投入或简化处理 |
| `紧急度 < 0 && 重要度 < 0` | 稍后处理 | 延后、删除或批量处理 |

任一维度为 `0` 的任务位于坐标轴上，标记为“待判断”，不计入四个象限的数量。这使默认 `(0, 0)` 不会被错误归类。

### 4.2 视觉编码

每个任务点使用统一尺寸的圆角色块：

- 背景色表示紧急度。
- 色块内的带符号数字表示重要度，例如琥珀橙色的 `+3` 表示坐标 `(+3, +3)`。
- 数字始终显示正负号，`0` 除外。
- 浅色背景使用深色文字，深色背景使用白色文字。
- 悬停、选中和键盘聚焦时显示任务名称、紧急度和重要度。

紧急度颜色表：

| 值 | 颜色 | Hex | 文字颜色 |
| ---: | --- | --- | --- |
| -3 | 深冷蓝 | `#354F9E` | 白色 |
| -2 | 亮蓝 | `#438FC1` | 白色 |
| -1 | 薄荷绿 | `#68BEB0` | 深色 |
| 0 | 中性灰 | `#737970` | 白色 |
| +1 | 橄榄黄 | `#BAA94E` | 深色 |
| +2 | 琥珀橙 | `#E38A39` | 深色 |
| +3 | 警示红 | `#D73D43` | 白色 |

颜色只做辅助编码。坐标位置、内嵌数字和详情标签始终同时存在，避免仅依赖色觉识别。

### 4.3 地图交互

- 拖动任务点时显示横纵参考线和实时坐标。
- 松手后吸附到最近整数格。
- 选中任务后，方向键逐格移动。
- `Return` 打开任务，`Space` 打开快速预览，`Delete` 需要二次确认。
- 同一坐标有 1 至 2 项时轻微错位显示；超过 2 项时显示数量堆叠，点击展开临时列表。
- 坐标变化立即更新象限、列表排序和指标，但不会自动修改日期或项目。
- 地图支持按项目、标签、时间范围和完成状态筛选。

任务列表的默认优先级排序依次为：重要度降序、紧急度降序、截止时间升序、创建时间升序。用户可以切换为手动、日期或创建时间排序。

## 5. 任务编辑

### 5.1 默认编辑界面

任务编辑器采用内容优先的写作式布局：

1. 标题。
2. 任务描述，支持轻量 Markdown 文本和链接识别。
3. 子任务列表和快速创建输入框。

子任务支持勾选、编辑、删除和拖拽排序。输入框按 `Return` 创建当前子任务并继续创建下一项。

用户只输入标题即可保存。编辑界面不默认展开日期、项目、标签、状态和坐标。

### 5.2 任务设置

右上角提供唯一的“任务设置”按钮。点击后以浮层或侧面检查器展示管理属性，排列顺序为：

1. 正方形优先级坐标盘。
2. 任务日期与提醒。
3. 预计时长。
4. 所属项目和看板列。
5. 完成状态。
6. 标签。

新任务默认值：

- 坐标：`(0, 0)`。
- 日期与提醒：无。
- 预计时长：无。
- 项目：无项目。
- 完成状态：未完成。
- 标签：无。

用户可以一键恢复默认设置。

### 5.3 快捷操作

- `Command-N`：新建任务。
- `Command-Return`：保存任务。
- `Escape`：关闭；存在未保存修改时确认。
- `Command-Shift-P`：打开任务设置并聚焦优先级坐标盘。

### 5.4 全局唤起快捷键

- 默认全局唤起方式为：`0.4` 秒内连续按下并释放两次 `Control`。
- 触发后只显示并激活 Task 主窗口；不创建任务、不切换视图、不隐藏窗口。
- 用户可在“设置 > 通用 > 唤起快捷键”切换为常规自定义组合键，或停用全局唤起。
- 双击 `Control` 只在两次按键间没有其他按键输入时触发，应用不得拦截或改变原始键盘事件。
- 双击 `Control` 依赖 macOS 输入监听权限。未授权时，设置页必须显示非阻塞说明和打开系统设置的入口；任务管理功能保持完整。
- 常规自定义组合键注册失败（系统保留或被其他应用占用）时，保留当前已生效的快捷键并显示可恢复错误。
- 快捷键配置只保存本机非敏感偏好，不写入 SwiftData、备份或日志。

## 6. 项目看板与指标

### 6.1 看板

新项目默认包含四列：待规划、本周计划、进行中、已完成。

- 用户可以新增、重命名、排序和归档非完成列。
- 完成列固定存在，但可以重命名。
- 任务拖入完成列时写入 `completedAt`；移出后清除。
- 每个项目必须且只能有一个完成列。
- 任务设置中的“完成状态”与看板完成列是同一状态：标记完成会把项目任务移入完成列；取消完成会移回该任务最近的非完成列，没有历史列时移入第一列。
- 看板卡片显示任务标题、优先级色块与重要度数字、日期和预计时长。
- 看板支持按优先级、日期、标签和手动顺序排列。

### 6.2 指标

看板顶部显示当前项目和时间范围内的指标：

- 完成率：截止时间落在所选范围内的任务中，已完成任务数 / 全部任务数；没有截止时间的任务不计入该指标。
- 高重要任务：`重要度 >= +3` 且未完成的任务数。
- 计划负载：截止时间落在所选范围内且未完成任务的预计时长总和；未填写预计时长的任务单独计数，不按 0 分钟掩盖。
- 计划健康度：0 至 100 的可解释分数。
- 完成趋势：按日或周统计完成任务数。
- 象限分布：四象限和“待判断”的任务比例。

健康度从 100 分开始扣减，并在 0 至 100 之间截断：

- 每个逾期未完成任务扣 6 分，最多扣 30 分。
- 每个“立即处理”但无日期的任务扣 4 分，最多扣 20 分。
- 计划负载每超出用户设定容量 1 小时扣 5 分，最多扣 30 分。
- 每个 `(0, 0)` 的待判断任务扣 2 分，最多扣 20 分。

界面必须展示扣分原因，不能只给出黑盒分数。

## 7. 可选 AI 规划

### 7.1 启用方式

AI 未配置时：

- 隐藏 AI 规划按钮和 AI 建议区域。
- 不显示错误、占位宣传或功能缺失提示。
- 所有本地任务、看板、指标和手动规划流程保持完整。

AI 配置后：

- 显示任务拆解、规划本周、依赖提示和风险提示入口。
- 首版支持 OpenAI-compatible Chat Completions 接口。
- 设置项包含 Base URL、API Key 和模型名称。
- API Key 存储在 macOS Keychain；Base URL 和模型名称存储在本地偏好设置。
- AI 服务通过内部协议隔离，后续可以添加其他服务适配器而不改动任务领域模型。

### 7.2 数据与确认流程

AI 不进行后台上传。只有用户主动点击 AI 功能时才开始以下流程：

1. 应用展示即将发送的任务范围和字段。
2. 用户可以取消选择具体任务。
3. 应用仅发送规划所需的标题、描述、子任务、坐标、日期和预计时长。
4. AI 返回结构化建议草案。
5. 应用校验响应并展示变更前后差异。
6. 用户逐项或全部确认后，才在单个本地事务中应用修改。

AI 永远不能直接删除任务。删除建议只能转化为“建议归档”，仍需用户确认。

### 7.3 AI 能力

- 拆解任务：根据标题和描述生成可编辑的子任务草案。
- 周计划：根据坐标、截止时间、预计时长和用户容量提出时间安排。
- 依赖发现：提示可能的先后顺序，不自动建立依赖。
- 风险提示：识别过载、日期冲突、缺少预计时长和高优先任务未安排。

AI 输出使用严格结构化数据模型。解析失败、超时、认证失败或限流时显示可恢复错误，不修改已有数据。

## 8. 本地数据模型

使用 SwiftData 保存领域数据。主要模型如下：

### TaskItem

- `id: UUID`
- `title: String`
- `details: String`
- `urgency: Int`，范围 `-3...3`
- `importance: Int`，范围 `-3...3`
- `dueAt: Date?`
- `reminderAt: Date?`
- `estimatedMinutes: Int?`
- `isCompleted: Bool`
- `completedAt: Date?`
- `previousBoardColumnID: UUID?`
- `manualOrder: Double`
- `createdAt: Date`
- `updatedAt: Date`
- `project: Project?`
- `boardColumn: BoardColumn?`
- `subtasks: [Subtask]`
- `tags: [Tag]`

### Subtask

- `id: UUID`
- `title: String`
- `isCompleted: Bool`
- `order: Int`
- `createdAt: Date`
- `task: TaskItem`

### Project

- `id: UUID`
- `name: String`
- `colorHex: String`
- `isArchived: Bool`
- `createdAt: Date`
- `boardColumns: [BoardColumn]`
- `tasks: [TaskItem]`

### BoardColumn

- `id: UUID`
- `name: String`
- `order: Int`
- `isCompletionColumn: Bool`
- `project: Project`

### Tag

- `id: UUID`
- `name: String`
- `colorHex: String?`
- `tasks: [TaskItem]`

任务坐标和预计时长在写入前验证范围。无项目的任务使用本地任务列表的泳道，`project` 为 `nil`。项目任务进入完成列时，`isCompleted` 必须为 `true`；离开完成列时必须为 `false`。删除项目时，任务默认移回无项目；只有用户明确选择时才级联删除。

## 9. 技术架构

### 9.1 技术选择

- 平台：macOS 14 及以上。
- UI：SwiftUI，必要时通过 AppKit bridge 提供窗口、菜单和拖拽细节。
- 本地数据：SwiftData。
- 网络：Foundation `URLSession`。
- 密钥：Security framework / macOS Keychain。
- 通知：UserNotifications。
- 构建：Swift Package + `.app` 打包脚本和 ad-hoc 签名，生成可双击运行并可移动到 `/Applications` 的原生应用。

### 9.2 模块边界

| 模块 | 职责 | 依赖 |
| --- | --- | --- |
| Domain | 模型、象限判断、排序、指标计算 | Foundation |
| Persistence | SwiftData 容器、查询和迁移 | Domain, SwiftData |
| Features | 地图、列表、任务编辑、看板、洞察、设置 | Domain, Persistence |
| AIPlanning | 服务配置、请求、结构化响应和差异审阅 | Domain, Foundation, Keychain |
| Notifications | 本地提醒授权和调度 | Domain, UserNotifications |
| AppShell | 窗口、导航、命令菜单和依赖装配 | 所有模块 |

领域层不依赖 SwiftUI 或 AI 服务，因此坐标、指标、排序和变更审阅可以独立单元测试。

## 10. 错误处理与数据安全

- SwiftData 写入使用明确的保存边界；批量变更失败时整体回滚。
- AI 建议应用前生成本地变更集，确认后一次提交。
- AI API Key 不写入日志、SwiftData、`UserDefaults` 或导出文件。
- 用户可以导出 JSON 备份；导入前先校验版本和字段范围。
- 无法打开数据库时显示恢复界面，提供重试和导出诊断信息，不自动清空数据。
- 日期和提醒使用用户当前时区保存绝对时间，界面按系统区域格式展示。
- 通知权限被拒绝时，任务仍可保存，只在设置中显示非阻塞状态。

## 11. 可访问性与原生体验

- 所有按钮、任务点和图表具有 VoiceOver 标签。
- 任务点标签读作“任务名，紧急度 X，重要度 Y，所属象限”。
- 地图支持完整键盘操作和清晰焦点环。
- 颜色不是唯一信息渠道；重要度数字和坐标标签始终可用。
- 支持系统浅色、深色模式和“减少动态效果”。
- 使用系统窗口控制、菜单栏命令、撤销/重做和标准快捷键。
- 文本支持 Dynamic Type 可用范围，紧凑工具区使用系统可读字号下限。

## 12. 测试策略

### 12.1 单元测试

- `-3...+3` 坐标验证和格点吸附。
- 四象限及坐标轴“待判断”分类。
- 7 级颜色映射和文字对比色选择。
- 列表排序、完成率、负载和健康度计算。
- 项目删除后的任务归属规则。
- AI 结构化响应解析、校验和变更集生成。

### 12.2 集成测试

- SwiftData 创建、编辑、迁移、删除和恢复。
- 任务拖入完成列后完成状态同步。
- AI 建议确认前后数据差异和失败回滚。
- Keychain 保存、读取和删除测试配置。
- 本地提醒新增、更新和取消。

### 12.3 UI 测试

- 新建任务只填写标题即可保存。
- 描述编辑、子任务连续创建和排序。
- 打开任务设置，优先级坐标盘位于顶部。
- 地图拖拽、键盘移动、同格堆叠和筛选。
- 未配置 AI 时所有基础界面无缺失或错误。
- 配置 AI 后规划草案必须经过审阅才能应用。
- 不同窗口尺寸下四象限始终保持正方形且无重叠。

## 13. 完成标准

首版完成时应满足：

- 可以构建并生成可双击运行的 `Task.app`。
- 首次启动无需账号和 AI 配置即可创建、编辑、完成和组织任务。
- 优先级地图严格按已确认的坐标、颜色和数字规则工作。
- 任务编辑器默认突出描述与子任务，管理属性只从“任务设置”进入。
- 看板、指标和项目流程使用真实本地数据。
- AI 配置存在时可生成可审阅草案；不存在或调用失败时不影响基础功能。
- 自动化测试覆盖核心领域规则，关键用户流程通过 UI 验证。
