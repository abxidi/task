# Task 交互可靠性与状态栏设计

日期：2026-07-15（2026-07-16 修订拖动动效）
状态：用户已确认，进入实施
范围：项目看板跨泳道拖动、全局唤起快捷键、系统状态栏入口。

## 1. 目标与边界

本增量修复看板卡片跨泳道拖动不连贯的问题，实现已批准的全局快捷键规格，并增加仅用于唤起主窗口的系统状态栏入口。

- 不修改 SwiftData 持久化模型、任务排序、完成列规则或优先级模型。
- 不增加后台分析、账号、同步或菜单栏独立任务管理功能。
- AppKit 仅用于全局键盘监听/注册、状态栏项和激活已有窗口；业务状态仍由 SwiftUI 与现有 repository 管理。

## 2. 看板拖动

`BoardDragCoordinator` 是 `@MainActor` 的视图状态协调器，保存活动任务 ID、源泳道 ID、全局指针位置和当前目标泳道 ID。它不写入 SwiftData。

- 卡片以 `DragGesture` 在看板内部移动；手势期间在根浮层显示固定宽度的完整卡片。浮层保持用户抓取点并直接跟随指针，不对连续位置更新做补间，避免产生拖尾或输入延迟。
- 拖动开始时，浮层在 `140 ms` 内轻微抬起并增强阴影；源位置保留 opacity `0.35` 的半透明占位，避免卡片瞬间消失或源泳道布局重排。
- 每个固定宽度泳道将全局 frame 报给看板；协调器据此确定目标泳道。目标泳道显示 `2 pt` 酸橙色内描边，并在任务最终排序位置显示与卡片等高的浅色临时占位。占位只参与展示，不改变列宽、不写入模型，也不增加首版不支持的泳道内手动排序。
- 目标泳道或目标位置变化时，占位和相邻卡片使用 `140 ms` 系统 ease-out 过渡。手势结束后，浮层在 `180 ms` 内落到目标占位，再调用现有 `BoardWorkflowService.move` 并清理协调器状态；只有目标与源泳道不同才写入数据。
- 在源泳道松手或拖出所有泳道时，浮层回到源占位后消失，不写入数据。按 `Escape` 取消时采用相同回位行为。
- 开启 Reduce Motion 时，浮层仍逐帧跟手，但取消缩放和跨位置飞行动画；源占位、目标占位与描边仅使用短暂淡入淡出。
- 现有 `dropDestination` / `onDrag` 路径移除，避免系统拖放预览与 SwiftUI 本地状态竞争。

## 3. 全局唤起快捷键

行为沿用 `2026-07-14-global-shortcut-design.md`：默认在 `0.4` 秒内双击并释放 `Control`，中间任何其他按键使序列失效。

- `GlobalShortcutConfiguration` 是 Codable 的本机非敏感偏好，模式为双击 `Control`、自定义组合键或停用。
- `DoubleControlDetector` 是无 UI、无 AppKit 依赖的状态机；配置、超时和干扰输入均可单元测试。
- `GlobalShortcutManager` 负责 `NSEvent` 监听、Carbon 自定义组合键注册及权限/注册状态。注册失败不替换当前仍生效的快捷键。
- 设置页“通用”顶部新增“唤起快捷键”表单区，提供分段控制、组合键录入、输入监听权限说明和系统设置入口。所有控件提供 VoiceOver 标签。
- 收到激活事件后，应用取消隐藏、激活，并将已有主窗口置前；不创建任务、不切换页面、不执行隐藏切换。

## 4. 状态栏入口

- `StatusBarController` 创建一个 `NSStatusItem`，只响应主鼠标单击并调用同一主窗口激活器。
- 图标使用 template image：用户提供的黑色圆角方形成为不透明白色形状，原荧光绿 `T` 从 alpha 蒙版中扣除为完全透明。图标不保留粉色背景或绿色像素。
- 图标不显示菜单，不支持点击隐藏窗口，也不存储额外偏好。
- 状态栏图标含 VoiceOver 标签“显示 Task 主窗口”。

## 5. 验收

- 跨泳道拖动中，源位置稳定保留、完整活动卡片连续跟手、目标位置出现浅色占位，目标变化时相邻卡片平滑让位，松手后活动卡片落入占位；只在不同泳道落位完成时更新任务。
- 连续指针更新不做隐式动画，拖动浮层不滞后于指针；抬起、占位变化和落位动画均在 `140–180 ms` 内完成。
- Reduce Motion 下不发生缩放或跨位置飞行，拖动、取消和数据规则保持可用且一致。
- 默认双击 `Control` 与可保存的自定义组合键均能唤起已有窗口；无输入监听权限与注册失败都有可恢复设置页状态。
- 单击状态栏白色镂空 `T` 直接显示并激活主窗口。
- 纯状态机和协调器有失败测试；完整 `swift test`、release build、打包及签名验证通过。
