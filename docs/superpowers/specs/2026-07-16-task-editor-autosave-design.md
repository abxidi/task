# Task 任务编辑器自动保存设计

日期：2026-07-16
状态：用户已确认，待实现

## 1. 变更目标

任务编辑器不再要求用户点击保存。标题、描述、子任务、优先级、日期、标签和完成状态的变更均自动持久化；编辑器只保留右上角关闭入口。

本变更只调整任务编辑器的保存交互，不改变任务领域模型、优先级范围、SwiftData 存储方式、提醒行为或 AI 审阅边界。

## 2. 交互规则

- 用户修改任一任务字段后，编辑器在约 `250 ms` 无进一步变更时自动保存。
- 新建任务在标题去除首尾空白后首次非空时创建；标题为空时不写入。
- 新建任务创建成功后，后续字段变更更新同一条 `TaskItem`，不会重复创建任务。
- 编辑已有任务时，字段变更更新当前 `TaskItem`。
- 点击右上角关闭时取消等待中的防抖任务并立即 flush 当前草稿，然后直接关闭编辑器。
- 不显示“保存任务”按钮、不显示“取消”按钮、不显示 `Command-Return` 保存提示，也不显示未保存修改确认。
- 完成状态保留在任务属性区，仍通过同一自动保存流程写入。

## 3. 持久化与失败处理

- 继续使用 `TaskRepository.saveNewTask` 和 `TaskRepository.updateTask`，不让 SwiftUI View 直接写入 SwiftData。
- 防抖任务只能有一个；新变更会取消旧任务，避免重复保存。
- 关闭前 flush 确保最近一次编辑不会停留在内存草稿中。
- 自动保存失败时保持编辑器打开，显示可恢复错误；后续变更可以再次触发保存。
- 只有自动保存成功后才同步提醒；提醒注册失败不回滚任务保存。

## 4. 实现边界

- `TaskEditorModel` 移除脏状态和放弃修改确认所需的 `original`、`isDirty` 及相关状态。
- `TaskEditorModel.existing` 支持新建任务首次保存成功后接收持久化实体。
- `TaskEditorSheet` 增加可取消的自动保存调度，并删除底部保存/取消操作区。
- 增加可单元测试的自动保存动作决策，覆盖空标题不保存、新建一次、后续更新和已有任务更新。
- 更新编辑器布局测试，确保保存和取消入口不再暴露。

## 5. 验收标准

- 新建任务标题非空后可自动创建，继续编辑不会生成重复任务。
- 已有任务修改任一编辑字段后无需点击按钮即可持久化，重新打开仍保留变更。
- 关闭编辑器前的最近一次变更可持久化。
- 编辑器界面不存在“保存任务”和“取消”按钮，也不存在未保存确认。
- 自动保存失败时不会静默丢失当前编辑器内容，且不影响继续编辑和重试。
- `swift test`、`swift build -c release`、`./scripts/package_app.sh` 和签名校验通过。
