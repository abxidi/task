# 任务列表快捷加入正在做池设计规格

日期：2026-08-02
状态：交互方向已确认，待书面规格审核
范围：仅为任务列表增加“快捷加入正在做池”入口；不改变正在做池既有数据模型和页面。

## 1. 目标

用户在任务列表浏览任务时，可以不离开当前列表，将任务快捷加入独立的“正在做”空间。该操作的默认状态为“专注”。已加入后，用户可直接在同一入口更新状态、编辑备注或移出正在做池。

正在做池始终是任务处理的专注化表现，而不是任务列表、项目看板或完成状态的替代品。

## 2. 已确认的交互

### 2.1 入口位置与视觉层级

入口只出现在任务列表中的任务卡片。它是完成 checkbox 与任务标题之间的 `scope` 图标按钮，点击目标固定为至少 `28 × 28 pt`。

- 任务卡右上角继续且只保留优先级色块与重要度数字；快捷入口不得进入、覆盖或挤压该区域。
- 右下角删除按钮的现有位置保持不变。
- 未加入正在做池时，入口在 hover 或键盘焦点时显示描边 `scope` 图标；卡片尺寸、标题行和元数据行均不得因此发生位移。
- 加入成功后，图标切换为当前状态对应的 SF Symbol，并使用酸橙色作为已加入状态；元数据行同时显示当前状态的文字标签，避免只依赖颜色或图标传达信息。
- 优先级标记保留原有的标题尾部空间，不因该入口改变其在右上角的 `24 pt` 角标布局。

任务列表复用 `BoardTaskCard` 时，通过任务列表专用的可选 action 注入该入口。项目看板、拖动浮层和其他 `BoardTaskCard` 使用处不传入 action，因此它们不展示该入口。

### 2.2 加入与后续管理

对尚未加入的任务点击入口时，应用立即创建或更新对应 `FocusEntry`：

```swift
FocusRepository(context: modelContext).upsert(
    task: task,
    state: .focused,
    note: ""
)
```

成功后卡片无需刷新整个列表，只更新为“专注”的已加入呈现。

对已加入的任务再次点击入口时，打开锚定于该图标的菜单，按以下顺序提供操作：

1. 专注
2. 暂停
3. 阻塞
4. 等待
5. 编辑备注
6. 移出正在做

选择前四项立即保存状态，并更新图标和元数据状态标签。选择“编辑备注”打开紧凑、锚定该入口的备注 popover；其中提供多行本地文本输入。用户完成编辑并离开输入控件时保存，保存失败则保留输入内容并显示可恢复错误。选择“移出正在做”删除该任务的 `FocusEntry`，卡片恢复未加入的入口状态。

同一任务最多有一条 `FocusEntry`。并发或重复点击必须归并为一次 upsert，不得创建重复记录。

### 2.3 右键菜单

任务列表中的任务卡片支持右键菜单，并与卡片内快捷入口复用同一组 `FocusPoolCardAction` 回调，确保两个入口的状态和保存结果完全一致。

- 任务未加入正在做池时，右键菜单显示“加入到正在做池”。选择后以 `.focused` 和空备注创建记录。
- 任务已加入正在做池时，右键菜单显示“正在做”子菜单。子菜单按顺序包含“专注、暂停、阻塞、等待、编辑备注、移出正在做”，行为与卡片内已加入入口相同。
- 右键菜单不包含任务完成、项目、泳道或优先级的修改操作；不会覆盖看板列标题已有的右键菜单。
- 项目看板和拖动浮层不显示正在做入口或正在做相关右键菜单。

### 2.4 状态展示

状态名称与符号沿用正在做页既有约定：

| 状态 | 文本 | SF Symbol |
| --- | --- | --- |
| `focused` | 专注 | `scope` |
| `paused` | 暂停 | `pause.circle` |
| `blocked` | 阻塞 | `exclamationmark.triangle` |
| `waiting` | 等待 | `hourglass` |

备注仅在“正在做”页的条目中持续可见；任务列表不额外展开备注正文，以维持列表的扫描密度。备注仍可随时通过已加入入口编辑。

### 2.5 数据边界与失败处理

本功能复用现有 `FocusEntry`、`TaskFocusState` 和 `FocusRepository`，不引入 SwiftData 模型变更或迁移。

加入、状态切换、备注保存和移出都只修改 `FocusEntry`。它们不得修改：

- `TaskItem.isCompleted` 或 `completedAt`；
- 项目归属或看板泳道；
- 优先级坐标、日期、标签、子任务或任务排序。

任务列表当前显示的任何任务均可加入，包括已完成任务，因为正在做池与完成状态独立。加入、移出和状态更新失败时，卡片保留最后一次成功保存的状态，并使用现有“操作失败”错误呈现；不得静默丢失备注或乐观显示未持久化状态。

## 3. 可访问性与键盘

- 未加入入口的 VoiceOver 标签为“加入正在做”。
- 已加入入口的 VoiceOver 标签包含当前状态，例如“正在做：专注，打开管理菜单”。
- 每个状态菜单项使用完整中文状态名称；“编辑备注”和“移出正在做”使用明确的动作名称。
- hover、键盘焦点和已加入状态均保持不小于系统可读对比度的非颜色信息（图标或文字标签）。
- `Return` 或 `Space` 在键盘焦点位于入口时执行与点击相同的行为；`Escape` 关闭菜单或备注 popover，不修改未保存的备注。
- 右键菜单项使用“加入到正在做池”与完整状态名称；已加入任务的“正在做”子菜单可由 VoiceOver 识别为菜单层级。

## 4. 实现边界

修改范围限于任务列表的任务卡展示和对现有 `FocusRepository` 的调用：

- `Sources/TaskApp/Features/Board/BoardTaskCard.swift`：添加可选、任务列表专用的正在做入口呈现与回调，不改变默认卡片行为。
- `Sources/TaskApp/Features/TaskList/TaskListScreen.swift`：查询 `FocusEntry`，将任务与条目关联，并处理加入、状态、备注与移出操作及错误呈现。
- `Sources/TaskApp/Features/Board/BoardColumnView.swift`：仅在任务列表使用的静态卡片上透传右键菜单 action；项目看板与拖动浮层维持默认呈现。
- 如有必要，新建小型纯展示组件以承载入口和状态菜单；该组件不直接访问 SwiftData。
- `Sources/TaskApp/Features/FocusPoolScreen.swift`、`FocusRepository` 和持久化模型无需因本功能改变其数据契约。

不增加看板入口、拖拽加入、批量加入、快捷键、筛选条件或新的导航项。

## 5. 验收与测试

实现前先覆盖以下失败用例，再写最小实现：

1. 任务列表传入正在做 action 时，入口位于完成 checkbox 与标题之间，优先级标记仍在右上角，删除入口仍在右下角。
2. 未加入任务点击后以 `.focused` 和空备注创建唯一 `FocusEntry`；重复操作不生成第二条记录。
3. 已加入任务可在四种状态间切换，且状态保存后能重新查询到。
4. 编辑备注后内容持久化，并在正在做页可见；保存失败时本地输入不丢失。
5. 移出正在做只删除 `FocusEntry`，不改变任务完成状态、项目、泳道或优先级坐标。
6. 看板卡片和拖动浮层默认不显示正在做快捷入口。
7. 未加入与已加入入口均具备约定的 tooltip、VoiceOver 标签及键盘可操作性。
8. 任务列表未加入任务的右键菜单可加入正在做池；已加入任务显示完整“正在做”管理子菜单；项目看板和拖动浮层不显示该菜单。
