# Task 编辑器备注自适应高度设计

日期：2026-08-06
状态：用户已确认，待实施

## 目标

任务编辑器的“任务备注”按实际文字行数占用空间，避免单行 URL 或短备注被固定的大输入区包围。此改动只覆盖任务编辑器内的快速备注区，不改变 Markdown 全屏编辑器、备注数据结构或自动保存流程。

## 交互与视觉

- 空备注和单行备注的可见高度均为 `32 pt`。
- 备注使用 `15 pt` 系统字体和 `20 pt` 文字行高。显式换行与因可用宽度产生的自动折行都计为一行。
- 编辑器随真实行数增高，最多显示五行，最大可见高度为 `112 pt`。
- 超过五行时，备注控件自身出现细微滚动条；编辑器外层和后续子任务、内联属性区不承担该溢出内容的滚动。
- 备注获得焦点不会再仅因焦点状态扩展。点击、键盘输入、粘贴、删除、窗口宽度变化都会重新测量高度。
- 子任务和内联属性区保持既有顺序与间距。备注区域的高度变化应平滑反映到编辑器 sheet 高度；sheet 仍受窗口可用高度 `88%` 限制。

## 实现边界

- 新增仅负责输入、布局测量和内部滚动的 AppKit 桥接组件。它封装 `NSTextView`/`NSScrollView`，通过布局管理器取得实际排版行数，避免按字符数估算而误判中英文、长 URL 或窗口变宽后的软折行。
- SwiftUI 的 `TaskEditorSheet` 只绑定 `TaskDraft.details`、接收已测得高度，并将高度通过回调传给 `TaskEditorOverlay`。领域模型、SwiftData 持久化及 `TaskEditorModel` 不感知显示高度。
- `TaskEditorOverlayLayout` 接受当前备注高度参与 sheet 尺寸计算；当可用窗口高度较小，继续由外层编辑器滚动，不压缩备注最小行高。
- 当前 Markdown 详情编辑器维持原有固定布局与保存行为。

## 测试与验收

- 为纯布局度量增加测试：一行最小高度、行数递增、五行上限、超出上限不再增长。
- 为 overlay 布局增加测试：备注高度变化会反映到期望 sheet 高度，且不会突破 `88%` 上限。
- 手工验证一行 URL、显式多行中文、长 URL 软折行、粘贴超过五行、缩放编辑器宽度、深色模式与 VoiceOver 标签。
- 不修改任务数据、自动保存时机或 Markdown 编辑器行为，因此不需要 SwiftData 迁移。

## 规范更新

本设计取代 `docs/ui/task-macos-ui-spec.md` 中“任务描述编辑器最小高度 `160 pt`”这一已不符合当前交互的尺寸要求；该规范已同步更新为本设计的自适应高度规则。
