# 正在进行双入口子任务创建设计

日期：2026-08-21
状态：用户已确认，进入实施

## 目标

让用户可在“正在进行”任务的未完成子任务列表上方或下方直接创建子任务，减少长列表中的滚动与排序操作。

## 范围

- 在 `FocusEntryRow` 的子任务标题下方增加顶部输入行，并保留现有列表末尾输入行。
- 顶部输入行提交后将新子任务插入任务全部子任务的首位；原有项顺延，完成项也保持相对顺序。
- 底部输入行继续将新子任务追加到任务全部子任务的末尾。
- 两个入口的视觉样式、`Return`、`Command-Return` 和空标题忽略行为保持一致。
- 为两个入口提供不同的 VoiceOver 标签，说明创建位置。

## 非范围

- 不改动任务编辑器的 `SubtaskEditor`，该入口仍仅在列表底部新增。
- 不修改 SwiftData 模型、附件关系、拖拽排序或完成状态规则。
- 不增加新的同步、AI 或后台行为。

## 实现方式

`TaskRepository` 增加首位插入方法：按现有 `order` 排序后创建 `order = 0` 的子任务，将原有项依次重编号为 `1...n`，然后在单次保存中写入。原有 `addSubtask` 维持末尾追加 API 和行为。

`FocusEntryRow` 使用两个独立的输入状态，复用同一输入行视图，并以创建位置参数连接到对应仓储方法。顶部入口位于“未完成子任务”标题之后，底部入口位于列表之后；任何一个入口提交成功后只清空自身文本。

## 验证

- 在 `TaskRepositoryEditingTests` 先写首位插入失败测试，覆盖重编号、相对顺序和完成状态不变。
- 在 `FocusPoolPresentationTests` 锁定双入口、位置、快捷键及可区分无障碍标签的展示契约。
- 运行聚焦测试、完整测试、release 构建、打包与签名检查，并在原生 macOS 运行态确认键盘与 VoiceOver 标签。
