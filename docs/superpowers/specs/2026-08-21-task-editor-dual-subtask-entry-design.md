# 任务编辑器上下子任务入口设计

日期：2026-08-21
状态：用户已确认，进入实施

## 目标

在任务编辑器的子任务工作区顶部新增一个“添加一个子任务”输入行，让较长的列表无需滚动到底部也能继续录入；底部的既有输入行保持可用。

## 交互与视觉

- 子任务为空时只显示一个底部追加入口；存在子任务时，上方和下方入口使用同一紧凑输入行视觉样式、占位文案和 `Return` / `Command-Return` 连续创建行为；VoiceOver 标签分别说明其位于列表上方或下方。
- 上方入口创建的未完成子任务插入当前未完成子任务的首位；已有子任务顺序后移，已完成子任务仍位于列表末尾。
- 下方入口继续将未完成子任务追加在未完成区末尾、已完成区之前，保持既有行为。
- 两个入口均仅在输入非空白内容时创建；创建后清空当前入口并保持该入口焦点，空白输入提交时释放焦点。
- 子任务的复选、编辑、附件、删除、拖拽排序和自动保存行为不变。

## 实现边界

- `TaskDraft` 提供首位插入操作并同时维护标题、完成状态和标识符数组的对齐。
- `SubtaskEditor` 只管理两个独立的暂存输入文本和焦点状态，通过现有 `onAdd` 回调明确传递首位或追加意图。
- 不修改 SwiftData 模型、`TaskRepository`、迁移策略或“正在进行”页面。

## 验证

- 领域测试验证首位插入后未完成子任务、完成状态和 UUID 对齐。
- App 展示契约测试验证两个入口和两个不同的可访问性标签存在。
- 执行 `swift test`、`swift build -c release`、打包和签名验证；手工检查任务编辑器在浅色、深色和长列表场景下的焦点与布局。
