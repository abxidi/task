# 正在进行子任务状态与并列关联设计

日期：2026-08-27  
状态：已实施

## 背景与已确认结论

“正在进行”原先将状态控件和备注绑定在整项任务上，并把未完成子任务放在独立的右列。这使用户无法判断一条状态或备注具体对应哪一个子任务。

用户已确认以下产品结论：

- 状态和备注必须跟随子任务，而不是整项任务。
- 原有任务级备注和状态无需迁移；可以删除。
- 左右两列等宽 `5 : 5`。
- 左列为任务标题及其未完成子任务；右列为逐行对应的“状态与说明”。
- 未开始的子任务不显示任何状态标记或备注。
- 已开始的子任务才显示“专注 / 等待 / 阻塞”及其备注。
- 左右需要有栏目分离，但同一子任务与其状态/备注必须被清楚读作一一对应关系。

本设计取代此前“任务级状态控件 + 详情列 / 子任务列 46 / 54”的正在进行卡片布局；不改变任务的项目、看板泳道、完成状态或优先级。

## 交互与视觉设计

每张正在进行卡保留任务标题、优先级色块和“移出正在进行”操作。标题下方是一个同源的双列表格，而不是两张松散列表：

```text
任务与子任务                       │ 状态与说明
□ 回归 P0 用例                      ● │ [专注] 正在执行回归
□ 收集 skill 结果                   ○ │
□ 补充策略平台能力                  ● │ [等待] 等待接口确认
```

- 双列在满足宽度下各占可用内容宽度的 50%；中心保留 `1 pt` 分隔线。
- 每条子任务和右侧信息使用同一个等高行容器、同一条水平分隔；中心节点位于行中心，形成克制的“连接点”。
- 已开始行使用极弱的酸橙色关联底纹，中心节点为对应状态的语义色；未开始行使用中性节点且右侧内容为空白。
- 右侧空白单元仍是完整可访问的“开始处理此子任务”按钮。鼠标悬停或键盘聚焦时显示轻量加号；激活后创建该子任务的状态记录，默认选择“专注”，并立即展开紧凑分段状态控件与备注编辑器。
- 右侧状态控件沿用既有三段轨道的颜色、顺序和 VoiceOver 文案；状态/备注仅影响该子任务。
- 子任务完成时，正在进行页面继续按现有规则隐藏该行，并删除其状态与备注；取消完成不会自动恢复，用户可再次“开始处理”。任务完成时仍移出正在进行池并删除其所有子任务状态/备注。
- 窄于双列最小宽度时卡片纵向堆叠：每一条子任务紧跟自己的状态/说明区，避免保留难以理解的跨列关系。

## 数据与迁移设计

`FocusEntry` 继续仅代表“任务已加入正在进行池”的一对一成员关系，用于任务排序、加入和移出行为；它不再拥有有效的状态或备注语义。

`Subtask` 增加可选字段：

- `focusStateRawValue: String?`
- `focusNote: String?`
- `focusUpdatedAt: Date?`

`focusStateRawValue == nil` 表示未开始；非空值仅允许规范化的 `focused`、`waiting` 或 `blocked`。通过 `Subtask` 的小型计算属性读写 `TaskFocusState?`，确保 UI 不直接解析 raw value。

为避免一次破坏性 SwiftData 模型删除，既有 `FocusEntry.stateRawValue` 与 `FocusEntry.note` 暂保留为不再读取的旧存储字段。首次进入正在进行池时，仓储在同一保存边界中清空所有旧字段，实际删除用户已授权删除的任务级状态与备注。新导出不写入旧字段；导入旧备份时忽略其中的旧状态/备注，只恢复任务的“正在进行”成员关系。备份 schema 已递增为 v3。

子任务新增的可选字段为加性 SwiftData 演进；不增加云同步、账号或网络访问。

## 仓储与备份边界

- `FocusRepository` 负责加入/移出任务、清理旧任务级元数据，以及开始、更新、停止子任务状态。
- `TaskRepository.setSubtaskCompleted` 负责完成子任务时清除该子任务状态；任务完成时继续删除 `FocusEntry`，其级联清理由仓储完成。
- `BackupSubtask` 承载子任务的可选状态、备注和更新时间；备份 schema 版本递增。
- 老备份的任务级 `BackupFocusEntry.stateRawValue` / `note` 仅用于向后兼容解码，导入时不再恢复。

## 测试与验收

1. 子任务默认没有状态；开始处理后默认进入 `focused`，创建独立备注。
2. 两个子任务的状态与备注可以独立更新，更新不影响任务项目、看板泳道和完成状态。
3. 完成某个子任务会清除该子任务的状态与备注；取消完成后仍是未开始。
4. 遗留任务级状态与备注在进入正在进行池时清空，且不再导出或从旧备份恢复。
5. 宽度充足时双列严格 `50 / 50`，共享行高、边线和中线节点；窄宽度下按同一子任务的成对信息纵向堆叠。
6. VoiceOver 可以读出“开始处理此子任务”、当前状态、备注编辑器及其关联子任务标题。
7. `swift test`、release build、打包、签名与旧优先级范围扫描全部通过。

## 取舍

- 采用“子任务可选字段”而非新的 `SubtaskFocusEntry` 模型：状态是子任务的一对零或一属性，字段模型更小且可以用 `nil` 精确表示未开始。
- 保留并清空旧 `FocusEntry` 字段，而非直接从 SwiftData schema 删除：避免无必要的破坏性 schema 删除，同时仍按用户授权永久移除旧备注与状态值。
- 采用共享行、中心节点和弱高亮（视觉草图 A），而非更强的连线：在明确一一对应的同时保持应用既有安静、信息密集的视觉方向。
